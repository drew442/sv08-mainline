# Roadmap

Use [the current release route](remaining-work-plan.md) for scope, order and completion. [Current handoff](../.codex/current-goals.md) identifies the next action. This roadmap is not a second queue.

1. Supported release/commissioning candidate path and clean-owner setup.
2. One source-bound, factory-capacity complete board candidate.
3. Attended commissioning and representative printing of the actual selected hardware.
4. Candidate-specific installation, required peripherals, update and independent recovery qualification.
5. Publish the supported release, artifacts/source/notices and tested user procedures.

LAN distribution initially; definition-bound MCU recommendations per release, with rollback notification and no automatic reflash. Preserve all mandatory capabilities and explicit deferrals in the canonical route. Do not reopen completed packages/update/recovery mechanisms just because historical evidence has honest limits.

[Historical roadmap and supporting observations](history/roadmap-through-20261116.md). Its old open decisions are not current: AGPL selection, native ARM host availability and full software recovery qualification are resolved. Hardware claims remain evidence-scoped.
