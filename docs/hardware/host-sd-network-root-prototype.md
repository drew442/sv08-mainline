# Disposable SD/NFS-root prototype

Date: 2026-09-25. Profile: `test-sv08-01`; host PCB marking
`H616_JC_6Z_V1.2` is owner-reported. This is an offline development
prototype, not a printable host image, supported recovery path, or physical
SD-boot result. The owner has permitted erasing the supplied SD card, but this
task writes only a regular image file.

## What the prototype does

[`build_sd_network_image.py`](../../scripts/build_sd_network_image.py) makes a
192 MiB image, below the measured 1,977,614,336-byte card. It places the
separately built SPL/TF-A/U-Boot at byte 8192, relocates the GPT table to sector
4096, and puts one FAT boot partition at byte 16 MiB. There are no persistent
U-Boot environment regions. The generated U-Boot has `ENV_IS_NOWHERE`, no RAUC
boot method, no boot-standard scanner, no `saveenv`, and no extra sunxi MMC
slot. Its board DT enables external SD as `mmc0` and disables Wi-Fi SDIO and
eMMC. Compiled default commands load only `mmc 0:1`, verify the script SHA-256,
then the script verifies the local kernel, initramfs and device tree hashes
before `booti`. The loader does not use Ethernet.

The unchanged 6.18.51 candidate kernel/initramfs uses DHCP and Debian's
`scripts/nfs` to mount a read-only NFS v3 root. The export is generated by the
builder and contains only a static diagnostic init and empty `/dev`, `/proc`,
`/sys`, `/data`, `/run` and `/tmp` directories; its manifest is SHA-bound to
the image receipt. There is no systemd, RAUC, printer service, user account,
SSH key, configuration or private data in the export. The init verifies the
read-only NFS root, rejects a root write, mounts `/data`, `/run` and `/tmp` as
tmpfs, prints the result on serial, and powers off. This proves the early
network-root path only; it cannot administer or print with the machine.

The source initramfs contains a `local-bottom/sv08-data` hook for the normal
eMMC host. Source inspection shows Debian's `local_bottom()` runs those hooks
only if `local_top_used` or `local_premount_used` was set. The NFS mount path
uses `nfs_top`/`nfs_premount` instead. In the disposable QEMU run, no eMMC
PARTUUID existed and the root probe still reached `/data` as tmpfs, which
corroborates that the local hook did not run. This branch behavior is offline
evidence; direct physical eMMC isolation remains unverified.

## Reproduction and evidence

The exact source pins and card geometry are in
[`sv08-sd-network-inputs.json`](../../configs/host-os/sv08-sd-network-inputs.json).
Use the pinned U-Boot and TF-A archives and two pinned Armbian board patches
listed there. A fresh ignored `local/` build directory is required. The
builder defaults to inspection; `--execute` creates only regular files. Its
required inputs are the pinned archives, patch directory, compressed kernel,
initramfs, board DTB, server IPv4 address and NFS export path. The builder
refuses input hash mismatches and reports the image, loader, boot payload,
compiled U-Boot config, generated script and export manifest hashes in
`composition.json`. A QEMU-only image uses `--server 10.0.2.2` and
`--export /srv/sv08-sd-nfs`; that address must not be used as a physical LAN
server address.

The offline QEMU harness is
[`host_qemu_sd_network.py`](../../tests/host_qemu_sd_network.py). It requires a
private network and mount namespace and a local package tree containing
`nfs-ganesha`, its VFS plugin, `rpcbind` and their shared libraries. The test
packages can be downloaded and extracted under ignored `local/` without
installing server services on the workstation or Beelink. The harness exports
only the generated root with `Access_Type=RO` and `Root_Squash`, runs the
**same raw kernel and unchanged initramfs bytes placed in the SD image** under
QEMU `virt` with USB CDC Ethernet and PCI 8250 serial, then stops the server
and repeats with it absent. Its temporary sockets and `/run` mount are inside
the private namespaces; it terminates QEMU, Ganesha and rpcbind. QEMU tests
the Linux DHCP/NFS path, not the H616 bootloader or actual SD priority.

The source initramfs waits up to 180 seconds for a missing network device and
uses further DHCP retries. `rootdelay=8`, `nfsvers=3,timeo=10,retrans=1,soft`
and `panic=0` yielded a bounded server-missing halt when a network interface
was present. An unplugged physical Ethernet cable may take longer; the first
physical trial needs supervised UART and a time limit. Neither U-Boot nor
Linux has an automatic fallback to eMMC in this image; failed SD ROM selection
is still an unknown and could instead boot the current eMMC trial.

The image's main GPT table is at sector 4096; partition 1 starts at sector
32768 and is 128 MiB. `sgdisk --verify` passed. Direct reads from the completed
image matched the loader and FAT partition source hashes; `mdir` listed the
four expected boot files. The compiled U-Boot config hash is
`9d583044e969dab5e93b91149cabf683ba8b8ac63790b13a1263c94f8e5eef10`.
Its DT exposes only `mmc0`; both `mmc1` and `mmc2` controller nodes report
`disabled`. `CONFIG_MMC_SUNXI_SLOT_EXTRA=-1` means SPL initializes no extra
controller beyond SD. These checks are offline and do not prove ROM selection
or safe behavior on the physical board.
The prototype records exact output hashes, but its GPT GUID, FAT volume serial
and U-Boot script timestamp are generated during composition; byte-for-byte
rebuild reproducibility remains open.

The QEMU run used QEMU 8.2.2, a 1 GiB `virt` machine, and temporary Ganesha
4.3 and rpcbind 1.2.6 binaries extracted under ignored `local/`. The same
kernel/initramfs hashes as the SD image booted by DHCP and mounted the NFS
export read-only. The probe printed
`SV08_SD_NFS_PASS root_ro=1 data_tmpfs=1 dhcp_address=1` after 27.51 seconds.
The kernel reported 906,996 KiB available from 1,048,576 KiB at early boot;
the three volatile mounts reserve at most 64 MiB and allocate on demand.
With the server stopped, DHCP still succeeded and initramfs halted without
running the root probe after 35.03 seconds. The harness exited and no QEMU,
Ganesha or rpcbind process remained. The results are in ignored
`qemu-result.json` and serial logs; only sanitized outcomes are recorded here.

## Physical gate and stop conditions

Before a supervised SD write/boot, independently review the final image bytes,
the compiled environment/device tree and this evidence. Reconcile the current
eMMC v5 A-slot trial under its separate reviewed procedure first; its
boot-health confirmation is masked and two attempts were left after the
recorded boot. Reserve a stable Beelink address, configure a temporary
read-only root export there from the sanitized generated tree, connect printer
Ethernet to the same LAN, and start receive-only UART capture before power-on.
Use the owner-approved spare SD only. If the UART does not clearly show the SD
loader, the boot path reaches eMMC/RAUC, the expected NFS root cannot be
mounted, the probe does not report a read-only root and tmpfs `/data`, or any
printer output activates, stop the trial and preserve the trace. Do not use a
failed boot as evidence of SD priority or eMMC isolation. The HDMI/GUI and
printer stack are outside this prototype. On success, the diagnostic init powers
the host off; removing the card and restoring normal power is a human step.

The H616 controller mapping comes from the pinned U-Boot source and Allwinner
H616 User Manual v1.0, §3, cited there. Source and offline evidence were
inspected on 2026-09-25.
