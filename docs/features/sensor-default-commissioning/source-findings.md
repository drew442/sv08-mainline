## Pull-up evidence and failure paths

`thermistor.PrinterThermistor()` explicitly defaults `pullup_resistor` to 4700 Ω and `inline_resistor` to zero; `Thermistor.calc_temp()` uses `R = pullup * adc / (1-adc)` before applying the curve. The hotend override is intentional preserved software evidence; changing it to 4700 simply because that is upstream's default changes conversion without proving the circuit. Neither value is a measured physical resistor. No ADC/reference voltage, board revision or resistor topology is established by software configuration.

Published primary schematic candidates are `upstream/sovol-sv08/Motherboard/H616_JC_6Z_V1_2_MCU.pdf` p1 (filename revision V1_2) and `Extra_MCU.pdf` p1 (revision not established here), vendor pin above. Relevant circuit resistor topology/value was **not checked in this session**: Poppler and installed Python fitz were unavailable. Do not promote schematic agreement or a physical pull-up claim. Even a published resistor value would need correlation to installed board/wiring; their revisions remain unknown.

`temperature_sensor.PrinterSensorGeneric` calls `heaters.setup_sensor`, then `setup_minmax` and callback registration; it returns temperature/status and a zero target without creating a heater output. `adc_temperature.PrinterADCtoTemperature.setup_minmax` converts bounds to ADC limits, configures 8 samples at 1 ms, reports every 0.300 s, with range check count 4. `HelperTemperatureDiagnostics` clarifies ADC-out-of-range errors. Keep bounds, stop on shutdown/out-of-range/implausible or rapidly changing values, and investigate identity/wiring/model instead of widening bounds or fitting the pull-up to one ambient point. `QUERY_ADC` can return last ADC and timestamp; its optional PULLUP-derived resistance is a calculation using the supplied resistor, not a resistor measurement.
