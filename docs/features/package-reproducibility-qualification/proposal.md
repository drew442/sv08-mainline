# Package reproducibility qualification

Perform two fresh builds in distinct workspaces for the project admission package and all six selected application packages (admission, Klipper, Moonraker, KlipperScreen, Mainsail and RAUC), using current pinned inputs and existing disposable tools. Qualify source compilation versus package assembly explicitly; supplier wheels/distro packages remain pinned inputs. Rebuild project-selected native helper/wheel inputs where required to close actual source reproducibility coverage. Reuse matching prior evidence only for unchanged supplier/dependency scope, not as a substitute for the requested new package pairs.

Acceptance: each selected pair has identical complete artifact bytes and reported SHA256, with exact sources/configuration/toolchains and commands recorded. Differing output must be diagnosed and repaired without hiding differences, changing functionality or silently replacing selected inputs. Relevant builder/provenance/refusal checks must pass for any repair. Publish reproducible instructions, source-bound measured evidence and a review PR. Full boot-image reproducibility and hardware qualification are separate; do not claim them. Preserve historical evidence.
