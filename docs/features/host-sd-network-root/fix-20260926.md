# host-sd-network-root: restore verified U-Boot hash command

Requirement: approved `snr-01` requires the SD loader to verify the boot script
and each kernel/initramfs/DTB payload before booting them.

Reproduction: the first physical SD trial selected the SD-specific U-Boot, then
printed the generic `hash` usage and stopped before Linux. The compiled config
had `CONFIG_CMD_HASH=y` and `CONFIG_SHA256=y`, but
`CONFIG_HASH_VERIFY` was unset. U-Boot compiles out the `-v` parser unless this
option is enabled; the existing script therefore could not perform its
hash-verification command.

Change: enable `CONFIG_HASH_VERIFY=y` and make `inspect_config()` require it and
`CONFIG_SHA256=y` in addition to `CONFIG_CMD_HASH=y`. Add regression coverage
for either verification prerequisite being disabled. No boot commands,
addresses, payloads, NFS policy or eMMC restrictions change.

Validation: four `tests.test_sd_network_image` tests pass. A fresh run of the
regular-file image builder rebuilt U-Boot 2026.07 with the pinned source
archives, TF-A, toolchain and source-date epoch; its receipt records the
corrected fragment hash and effective config with all three required hash
symbols. The U-Boot sandbox test `ut dm cmd_hash_sha256` passes with hash
verification enabled. The corrected 192 MiB candidate passed GPT verification
and FAT inspection; its SHA-256 is
`53cc0b2696add39dae24480167d79807e72a15f824fbc9025aaf20a9aa63d08a`. The
matching private receipt is `local/sd-network-physical-20260925/composition-v2.json`.
Independent review returned **GO WITH CONDITIONS** for this exact hash. The
actual H616 Linux/NFS path remains untested.

Human dependency: [H09](../../hardware/coordinated-human-tasks.md) requires a
reviewed SD rewrite/readback and one supervised retry. No eMMC or MCU write is
part of this fix.
